What runs where in the plant dashboard

One diagram per build: which thread each widget and data job runs on, and how records move between them. A box is a thread; a card inside it is an isolate or a group of isolates, with its count. Machine T3 is drawn in full and stands for each of the eight machines. The builds come in pairs that run on about the same number of threads.

Everything on one thread

  • Native: the page, all 72 widgets and the 33 data jobs share the main thread, with a store on the page.
  • Isoloop one: the same 105 pieces become isolates in one pool, so they move off the main thread to one worker, with the bus on its own worker.

Data on workers

  • Native + workers: each machine's data jobs run on their own worker (9 workers in all); the 72 widgets stay on the main thread.
  • Isoloop matched (the default): the same 9 data threads, and the 72 widgets move to one visual pool off the main thread: 10 threads plus the bus.

More threads

  • Isoloop split: compared with matched, each machine's widgets get their own visual pool and the fleet widgets another, so a blocked widget stalls only its machine: 18 threads plus the bus.
  • Isoloop own: every isolate on its own worker, 105 threads plus the bus, so a block stops only that isolate.
